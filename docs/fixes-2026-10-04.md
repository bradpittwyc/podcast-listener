# 2026-10-04 播放与全应用检查修复

基于 `6b6e029`，在 `mobile-ui` 工作树修复。共享前端同时影响 Web、手机和平板。

## 已确认的六个问题

1. 播放结束清理播放意图和等待状态，返回前台及迟到字幕不会重播；主动点击播放才从头重播。
2. 所有跳转统一协调播放状态。等待时拖回已覆盖字幕范围立即恢复；手动暂停继续保持暂停。A–B 循环先跳到 A，再判断字幕覆盖。
3. 外部 RSS 数据、收藏 URL、单词与频道标识改为转义后的 `data-*` 和事件委托，避免拼接内联 JavaScript；错误文本也进行 HTML 转义。
4. 按节目保存最多 200 条播放进度，迁移旧记录；冷启动只展示首页，用户选择旧节目才恢复位置、倍速和音量，等待该位置字幕就绪。
5. 助教请求使用取消控制和对话版本。换节目或清空对话后旧回答不写入；请求结束不清除新选择，包括发送期间重新选择同一句。180 秒超时支持重试。
6. 替换 Android API 24 才支持的集合调用，保留 `minSdk=23`。修复本机未提交的 SDK 路径转义；Lint 通过，没有关闭检查或添加错误基线。

## 专项风险处理

- 进程内 WebView 由前台服务保留，Activity 销毁时只脱离界面，重建时复用。整个进程结束后重新启动仍进首页。
- Android 解码先定位到断点前的帧，只丢弃重叠部分。Web 未完整缓存时仍需重新解码前缀，但只在实际解码前进时延长前端进度等待，不把心跳误当进度。
- 音频网络错误独立退避恢复，保留播放位置；最多自动恢复六次，手动暂停或换节目取消重试。缓冲期间仍正常播放时不因 `stalled` 重载音频。
- 启动时按节目清理闲置缓存，Web 2 GiB、Android 转写记录 64 MiB、闲置 30 天。设置、密钥、笔记不参与清理；这是启动时策略，单次长时间进程内仍可能暂时超过阈值。
- 字幕只更新改变的行并追加新行，收藏匹配使用排序后二分查找；保留未变化的 DOM 与当前句高亮。
